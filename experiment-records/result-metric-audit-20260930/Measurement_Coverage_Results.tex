\subsection{Measurement coverage and interpretation}\label{sec:result-metric-coverage}\label{app:four-condition-diagnostics}
Results are reported separately for each run. Completion latency, unfinished-message percentage and SLO violations use distinct messages produced during evaluation and successfully accepted by Kafka. These messages are followed until the end of drain. Completion is measured when application processing finishes, before offset-commit acknowledgment. Warm-up messages are excluded from these three measurements, but any remaining warm-up work can delay evaluation messages and contribute to backlog and throughput.

The experimental latency SLO is completion within one second of production. A violation occurs when an evaluation message finishes after one second or remains unfinished after that time has elapsed. This threshold was specified before the four-partition experiments and was also applied to the saved records from earlier experiments.

Lag, throughput, CPU and memory time-series plots cover the evaluation period. Throughput counts distinct message completions during evaluation and can therefore include warm-up messages. Requested resource cost and CPU and memory use accumulated over time cover only consumers during evaluation and drain, excluding warm-up. Measured CPU and memory use are reported separately from requested resources. Missing or invalid observations remain gaps rather than being treated as zero. Growth and windowed measurements are not calculated across missing observations or changes in partition ownership.

The message-record and partition-handover checks passed, and no repeated message completions were recorded in the ten-minute experiments. Each run remains visible in the results so that differences between the two repetitions can be assessed.

The diagnostic figures show the number of persistent hot partitions, the lag skew ratio, and maximum and mean partition lag. They use the definitions and thresholds given in the Metrics section. A partition must be hot at the current observation and in at least twelve of fifteen consecutive valid observations to be classified as persistently hot. Missing observations or ownership changes restart this observation window.

The runtime-state figures show $\mathcal{X}(t)$, combining average backlog, backlog growth, lag skew and persistent hot partitions. Backlog, skew and persistence use fifteen observations taken two seconds apart, spanning 28 seconds. Average growth uses fifteen two-second intervals, spanning 30 seconds. The separate processing-backlog growth plots use a ten-second interval. The persistent-hot curve shows the number of partitions in $H_{\mathrm{persistent}}(t)$. These measurements describe the conditions before and after scheduled mitigation; automatic decisions by the planned controller remain to be evaluated.

Consumer-position lag measures progress in receiving messages, whereas processing backlog also includes received messages that have not finished processing. The unfinished-message curves include warm-up messages, while the reported unfinished percentage includes only evaluation messages. Table~\ref{tab:result-metric-coverage} in Appendix~\ref{app:measurement-coverage} lists where results for each metric are reported.
