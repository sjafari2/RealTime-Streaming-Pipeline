\subsection{Twelve high-input partitions: ten-minute evaluation}\label{sec:twelve-partition-updated}\label{sec:four-condition-results}
At a total input rate of 700 messages/s, twelve of sixty partitions received 80\% of the input and initially belonged to Consumer 2. The other 48 shared the remaining 20\%. Eight trials compared keeping three consumers, redistribution within three, scaling to six with targeted redistribution, and scaling to six with Kafka's normal Cooperative Sticky rebalancing. Each response was tested twice using workload seeds 81 and 82, with the run order reversed in the second repetition. Initial ownership, consumer placement and resource settings were checked. Runs used one minute of warm-up, ten minutes of evaluation and two minutes of drain, with intervention after the first evaluation minute. Other settings are in Table~\ref{tab:config}.

All three interventions completed the evaluation messages by the cutoff, while the unchanged assignment left substantial unfinished work. Normal Kafka scaling achieved the lowest p99, whereas redistribution within three used fewer resources. Targeted scaling recovered sooner than redistribution but had higher p99 and fewer one-second SLO violations. Thus, faster backlog recovery did not necessarily give lower completion latency. Tables~\ref{tab:twelve-partition-outcomes}--\ref{tab:twelve-partition-intervention-cost} report the values. Targeted and normal scaling also use different assignment mechanisms, as described in Section~\ref{sec:targeted-reassignment}.

Persistent hot partitions were observed before intervention. None remained at valid observations in the final two evaluation minutes of the redistribution and targeted-scaling runs. Relative skew could still rise while absolute backlog fell, so the skew and persistence plots must be interpreted alongside total backlog and growth.

Resource measurements use valid observations. Per-process CPU coverage ranged from 87.50\% to 99.72\%; the interval includes time before added consumers started. The first unchanged run lacks sufficient requested-resource history for a full-period cost comparison.

In the intervention table, \emph{decision to active} ends when ownership is verified, while \emph{global gap} is the longest interval with no consumer processing. Extra pending work is measured during the processing pause; net pending change covers the full transfer, so negative values mean unfinished work decreased. Recovery is measured from the decision to confirmation of the low-backlog criterion while input continues.

Redistribution had lower p99 and used less CPU and memory in both runs during this interval. Both responses sustained approximately 700 completions/s without persistent hot partitions. Targeted scaling therefore cleared the earlier backlog sooner but did not reduce later-message p99. The SLO results varied between runs, so neither response was better for every metric.
